# RomM on Dokploy

Docker Compose deployment of [RomM](https://romm.app) for a VPS managed by
[Dokploy](https://dokploy.com). Game files, saves and config live on the host
under `/srv/library/games` (ROMs) and `/srv/apps/romm` (assets, config, resources); the database and redis use named volumes.

## 1. Prepare the host

```bash
sudo mkdir -p /srv/library/games/roms /srv/apps/romm/{assets,config,resources}
```

| Path                 | Container path   | Contents                          |
| -------------------- | ---------------- | --------------------------------- |
| `/srv/library/games`  | `/romm/library`  | ROM files                         |
| `/srv/apps/romm/assets`   | `/romm/assets`   | Saves, states, screenshots        |
| `/srv/apps/romm/config`   | `/romm/config`   | Optional `config.yml`             |

If the ROM collection will not fit on the system disk, mount block storage at
`/srv/library/games` before the first deploy.

## 2. Generate secrets

```bash
openssl rand -hex 32      # ROMM_AUTH_SECRET_KEY
openssl rand -base64 24   # DB_PASSWD
openssl rand -base64 24   # MARIADB_ROOT_PASSWORD
```

## 3. Create the Compose service in Dokploy

1. **Create Service → Compose**, source **Git**, repository
   `git@github.com:andreferrazz/romm.git`, branch `main`, compose path
   `./docker-compose.yml`.
2. In **Environment**, add the variables from `.env.example`:

   ```
   DB_PASSWD=
   MARIADB_ROOT_PASSWORD=
   ROMM_AUTH_SECRET_KEY=
   SCREENSCRAPER_USER=
   SCREENSCRAPER_PASSWORD=
   RETROACHIEVEMENTS_API_KEY=
   STEAMGRIDDB_API_KEY=
   ```

   The first three are required. The metadata provider keys can stay empty;
   see the [provider docs](https://docs.romm.app/latest/getting-started/metadata-providers/)
   to fill them in later.
3. **Deploy**.

## 4. Add the domain

In the service's **Domains** tab add your hostname, choose service `romm`,
container port `8080`, and enable HTTPS. Traefik handles the certificate.

The compose file does not publish any ports. The `romm` service joins
`dokploy-network` so Traefik can reach it; `romm-db` stays on the private
compose network only.

## 5. Add games

Copy ROMs to the host using RomM's platform slugs as folder names:

```
/srv/library/games/roms/
├── gba/
├── n64/
├── ps1/
└── snes/
```

```bash
rsync -avP ./roms/ user@vps:/srv/library/games/roms/
```

Then open the web UI, create the admin user on first launch, and run a scan.
The accepted folder structure and slugs are listed in the
[RomM README](https://github.com/rommapp/romm?tab=readme-ov-file#folder-structure).

## Backups

- `/srv/library/games` (ROMs) and `/srv/apps/romm` (assets, config)
- MariaDB: enable a scheduled backup in the Dokploy service's **Backups** tab,
  or run `docker exec romm-db mariadb-dump -u root -p"$MARIADB_ROOT_PASSWORD" romm > romm.sql`.

The `/srv/apps/romm/resources` directory and the `romm_redis_data` volume are caches and can be
regenerated by rescanning.

## Updating

Redeploy from Dokploy. The `romm` image is tracked at `latest`, so a redeploy
pulls the newest release.
